Запуск у RStudio (робоча папка = code) — ОДИН файл:
  source("run_all_v6.R", encoding = "UTF-8")
  Прапорці на початку run_all_v6.R:
    UPDATE_DB  TRUE  -> 01: дозавантажити нове з API НБУ (лише останні 3 міс. + нові місяці)
    CHECK_DB   TRUE  -> 01b: перевірка бази -> output_nbu\logs\db_check_v6.csv
    BUILD      TRUE  -> 02: перебудувати марти з бази (офлайн)
    MODELS     c("03","04","05") -> моделі; вони ЛИШЕ читають марти, нічого не завантажують
  Після виправлень у коді 02 (як k140 у MIR) перезавантажувати базу НЕ потрібно: UPDATE_DB <- FALSE.

  Шари: база (raw_*) -> марти (mart_*, macro_monthly_v6) -> моделі (03–05).

Старі скрипти (v5.2, 02_section_2_1_deep_analysis.R) і старі parquet НЕ видаляються:
v6 повторно використовує вже завантажені raw_*.parquet і дописує лише нове.

Головні методологічні зміни v6 (див. коментарі у 02_build_marts_v6.R):
  1) нетто-обороти (дебет − кредит) замість валового дебету — прибирає сторно-піки 2019-05, 2023-07;
  2) річна ставка = (днів у році / днів у місяці) × потік / середній залишок;
  3) лаг залишку за календарним місяцем; системні ставки — на узгодженій вибірці;
  4) повні групи рахунків 260/262 (+2606, 2621, 2624), НБФУ, оптове фондування, кредити, ЦП;
  5) валютний розподіл процентних витрат — через нарахування 2608/2618/2628/2638
     (рахунки класу 7 ведуться ЛИШЕ в гривні, тому v5 показував валютну вартість = 0);
  6) автоматичне виявлення перекласифікацій «вимога ↔ строкові» (напр. nkb 46, 2023-07).

Чорно-білий стиль (за замовчуванням, 04.11.2026): utils_figures_bw_v6.R
  лінії — відтінки сірого + типи ліній (+ маркери, якщо рядів ≥ 3); точки — форми маркерів;
  стовпці й площі — тони сірого + штрихування (45°, −45°, сітка, горизонтальне), у легенді те саме;
  фази циклу — світло-сірі смуги. Штрихування малюється лініями, тому працює і в EMF (Word).
  Кольоровий варіант: Sys.setenv(THESIS_FIG_STYLE = "colour") перед запуском.
