# Оновлення коду в RStudio

Новий коміт на GitHub не змінює файли у відкритому RStudio автоматично.

## Якщо проєкт клоновано з GitHub

1. Збережіть файли. Перегляньте локальні зміни у вкладці Git і зафіксуйте потрібні зміни комітом перед оновленням.
2. Виберіть потрібну гілку, зазвичай `main`, та натисніть Git → Pull. Якщо є конфлікти, спершу вирішіть їх. Не видаляйте свою роботу для примусового оновлення.
3. Перевірте останній коміт у Git → History. Перезапустіть R через Session → Restart R.
4. Запустіть із кореня проєкту наступний код.

```r
Sys.setenv(THESIS_CODE_DIR = normalizePath(getwd()), THESIS_UPDATE_DB = "false")
source("run_all_v6.R", encoding = "UTF-8")
```

Pull оновлює відстежувані файли коду поточної гілки. Результати моделей перераховуються після запуску. Після змін залежностей повторіть встановлення з `requirements.txt` та `00_install_packages.R`.

## Якщо проєкт відкрито з розпакованого ZIP

ZIP не має Git-зв’язку, тому Pull недоступний. Створіть File → New Project → Version Control → Git і клоніть `https://github.com/Havrilukuriy2004/oneu-thesis`. Скопіюйте в клон папки `data_nbu` та `output_nbu` з остаточного архіву, зокрема обидва Excel-файли у `data_nbu/local_inputs`. Відкрийте `.Rproj` саме в клоні. Надалі використовуйте Pull.

Ці папки даних і результатів не відстежуються Git. Pull не завантажує й не перезаписує їх. Старий архів може не містити останніх файлів капіталу, тому для першого налаштування потрібен остаточний архів. Автоматичний імпортер сам перебудує таблицю капіталу, якщо зміниться його код або вхідні файли.

## Статус перевірки

Python-оцінки та перевірки виконані на наданій панелі. Повного числового запуску змінених R-моделей у середовищі перевірки не було. Зелений CI засвідчує синтаксичні перевірки, а не числову валідацію R-результатів.
